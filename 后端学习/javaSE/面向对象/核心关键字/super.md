#### 1. `super` 与 `this` 的本质区别

- **`this`**：代表**当前对象**的引用，指向当前正在创建或调用的子类对象总内存。它会先从子类自己身上找，如果子类没有，就会顺着继承链去父类身上找。
    
- **`super`**：代表**当前对象的父类型特征**。它会**绕过子类**，直接去父类（及更上层父类）身上找。

- super相当于一个标签贴在子类对象的父类属性上，方便使用super查找父类属性。不是一个独立的指针/引用，它不需要也**没有独立的内存地址**。它的本质是 JVM 编译期的一枚“内存定向标签”**，精准贴在子类对象内部的**“父类型特征区”。
    
- **打印差异**：`this` 可以单独输出（打印对象地址），`super` **绝对不能单独输出**（编译报错），因为它只是个语法限定符，必须以 `super.属性` 或 `super.方法()` 的形式作为向导路标使用。

#### 2. `super` 的使用限制

- **不能在静态上下文中使用**：`super` 与 `this` 一样都依赖实例环境。在 `static` 修饰的静态方法、静态代码块中，**绝对不能**使用 `super`。
    

#### 3. “`super.`” 什么时候不能省略？
如果子类中没有同名变量，那么不管是通过 `this.变量` 还是 `super.变量`，它们最终**指向的都是同一个内存地址里的同一个变量**（即父类中定义的那个变量）。

当父类和子类中定义了相同的属性（实例变量）或相同的方法（实例方法/重写）时：

当子类定义了和父类一模一样的实例变量时，在内存中（堆内存的对象内部），其实**同时存在两个变量**：一个是父类的，一个是子类的。这种现象叫做**属性遮蔽（Field Shadowing）**。

- `this.变量` 访问的是**子类自己**的变量。
    
- `super.变量` 访问的是**父类**的那个变量。 它们由于指向不同的内存空间，值和地址都是**不相等**的。

```
class Father { String name = "父类"; }
class Son extends Father {
    String name = "子类";
    public void show() {
        System.out.println(name);       // 输出: 子类 (就近原则)
        System.out.println(super.name); // 输出: 父类 (显式指定super，不可省略)
    }
}
```

#### 4. `super(实参);` 的核心作用与物理动作

- **作用**：通过子类的构造方法去**调用父类的构造方法**。
    
- **目的**：为了完成子类对象中**父类型特征（那块包裹在内部的父类属性空间）的初始化**。
    

#### 5. `super(实参);` 的位置铁律

- **铁律**：`super(实参);` **只能出现在子类构造方法的第一行**。
    
- **原因**：必须保证在子类特有属性初始化之前 cooking 好父类的特征。同时，它与 `this(实参);` 相互排斥，二者只能择其一放在第一行。
    

#### 6. 构造方法第一行的默认机制

当一个构造方法的第一行**既没有**显式调用 `super(实参);`，**也没有**显式调用 `this(实参);` 时，系统（编译器）会自动在第一行塞入一个无参数的 **`super();`** 去调用父类的无参构造。

> **最佳实践**：为了防止子类编译报错，只要类中写了带参构造，**务必手动把无参数构造方法也写出来**。

#### 7. 溯源：Object 顶层构造方法的必然执行（新增 ⑧）

在 Java 语言中，**只要 new 对象，`Object` 类的无参数构造方法一定一成不变地会执行。**

#####  构造方法调用链（Constructor Chaining）原理

Java 的继承是一棵树，所有类都隐式或显式地继承自 `java.lang.Object`。 当你 `new Son()` 时，会触发以下链式反应：

1. 调用 `Son` 的构造方法。
    
2. `Son` 构造方法第一行默认执行 `super()`，调用 `Father` 的构造方法。
    
3. `Father` 构造方法第一行再次默认执行 `super()`，调用 `Object` 的构造方法。
    
4. `Object` 的构造方法最先执行完毕，然后弹栈，接着执行 `Father` 的构造方法体，最后才执行完 `Son` 的构造方法体。
    

###  核心总结：一个 Java 对象诞生的完整宏观流程

结合之前的笔记，现在你可以闭环整个对象的创建心法了：

1. **`new` 触发**：在堆内存开辟一块连续大空间，所有属性赋系统默认值（`0`/`null`），**【对象创建完毕】**。
    
2. **标签定位**：`this` 标签贴在最外层，`super` 标签贴在内层父类特征区。
    
3. **顶层溯源**：从子类构造方法第一行开始“套娃”向上追溯，直到 **`Object` 类的无参构造方法在栈顶率先执行**。
    
4. **自顶向下初始化**：从顶层类开始，层层向下执行构造方法体，用实际参数覆盖默认值，**【对象显式初始化完毕】**。
