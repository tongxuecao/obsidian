### 一、Java 程序两大阶段

#### 1. 编译阶段（静态绑定）

以 `Animal a2 = new Cat();` 为例：

1. 编译器仅识别引用**声明类型 `Animal`**
2. 去父类 `Animal` 查找 `move()` 方法
3. 找到方法完成**静态绑定**，编译正常通过

#### 2. 运行阶段（动态绑定）

1. JVM 读取堆中**真实对象类型 `Cat`**
2. 执行子类重写后的 `Cat.move()`
3. 该机制称为**运行期绑定 / 动态绑定**

### 二、多态核心定义

同一个引用变量，编译期表现为父类形态，运行期表现为子类形态，两种形态差异，因此命名为**多态**。

### 三、向上转型和向下转型

两种类型要有继承关系，没有继承关系编译器报错

#### 向上转型（Upcasting）

向上转型就是**把子类对象赋值给父类（或接口）的引用**。这在面向对象中被称为 `is-a` 关系。例如：猫（子类）是一只动物（父类）。

- **语法**：`父类类型 引用名 = new 子类类型();` （自动转换，不需要强转）
    
- **特点**：
    
    - **安全性**：绝对安全。因为子类继承了父类，父类拥有的属性和方法，子类一定都有。
        
    - **可见性变化**：转型后，该引用**只能调用父类中定义的方法和属性**，子类特有的方法和属性会“隐藏”起来，无法直接调用。
        
    - **动态绑定**：如果子类重写（Override）了父类的方法，通过这个引用调用该方法时，**执行的是子类重写后的逻辑**（这就是多态的精髓）。

使用传参的方式来使用上转型对象
喂宠物为，Pet为宠物类，Cat和Dog都继承Pet，重写Pet中的feed()的方法例：
```
test.java

...
Cat cat=new cat();
Dog dog=new dog();
Master master=new master();
master.feed(cat);
...

Master.java
...
public void feed(Pet pet){
	pet.feed();
}
...
//相当于Pet pet=new Cat();或者Pet pet=new Dog();
```





#### 向下转型（Downcasting）

向下转型则是反过来，**把父类引用强制转换为子类的引用**。

- **语法**：`子类类型 引用名 = (子类类型) 父类引用;` （必须显式强制转换）
    
- **为什么需要它？** 当我们通过向上转型隐藏了子类特有的方法（如上面的 `bark()`）后，如果后续业务逻辑**又需要用到子类的特有功能**，就必须通过向下转型把引用“还原”回去。

##### 向下转型的风险：`ClassCastException`
例：

```
Animal x = new Cat();  // 向上转型
Bird b = (Bird) x;     // 向下转型 -> 编译通过，运行报错
```

编译器只判断是否有继承关系，在运行阶段，通过对象名x去堆内存找真正的对象，发现x是Cat的对象，无法转为Bird的对象，抛出`ClassCastException`（类型转换异常）

## 四、`instanceof` 关键字

为了避免向下转型时发生崩溃，Java 提供了 `instanceof` 关键字，用于在转换前**判断某个引用指向的实际对象是否属于某种类型**。

### 示例代码

```
public void act(Animal animal) {
    animal.eat(); // 向上转型带来的通用行为

    // 如果想调用子类特有行为，先用 instanceof 校验
    if (animal instanceof Dog) {
        Dog dog = (Dog) animal; // 安全的向下转型
        dog.bark();
    } else if (animal instanceof Cat) {
        Cat cat = (Cat) animal;
        cat.meow();
    }
}
```

> **💡 Java 14+ 模式匹配优化：** 如果你使用的是现代 Java 版本，可以使用更简洁的 `instanceof` 语法，省去手动强转的步骤：

```
 if (animal instanceof Dog dog) {
     dog.bark(); // 直接使用 dog 变量，无需显式强转
 }
```

IDEA中的快捷方式：
alt+insert：插入重写方法、getter and setter方法，toString 方法
对于下转型对象：键盘输入  b.castvar 创建b的下转型对象


### 五、多态的作用

如果没有多态，我们在写代码时就需要针对每个具体的子类去写专门的方法，导致代码臃肿且难以扩展。而有了多态，我们可以带来以下巨大优势：

- **消除了类之间的耦合关系**：调用者只需要关注父类（或者接口）是怎么定义的，不需要关心具体的子类是怎么实现的。
    
- **极强的可扩展性（符合开闭原则）**：如果以后想增加一只“鸭子”类，只需要让它继承 `Animal` 并重写 `makeSound()` 即可。原来的测试主程序（`Main` 中的调用逻辑）完全不需要做任何修改，直接就能接入使用。
    
- **接口重用**：一次定义，多次实现，让代码结构更加清晰。

多使用多态能够降低耦合度，提高拓展性，符合OCP（开闭原则）
