## 一、 继承（Inheritance）的核心语法与四大能力

### 1. 核心大局观

- **是什么**：子类通过 `extends` 关键字继承父类，是对父类的**扩展（Extension）**。
    
- **为什么**：**代码复用**（抽取共性，减少冗余） + **多态基石**（没有继承和重写就无法实现多态）。
    
- **三大铁律**：
    
    1. **单继承性**：Java 类只能有一个直接父类，避免菱形继承冲突。
        
    2. **多层继承**：支持祖孙多层结构（A -> B -> C），C 间接继承 A。
        
    3. **顶层老祖宗**：所有 Java 类（除 Object 本身）都直接或间接继承自 `java.lang.Object`。
        

### 2. 子类的“四大能力”

- **用（继承）**：自动拥有父类所有**非 private** 的属性和方法。
    
- **加（扩展）**：定义子类特有的新属性和新方法。
    
- **改（改造）**：**方法重写（Override）**，保持方法签名不变，重写业务逻辑。
    
- **引（重构）**：在构造方法第一行通过 `super()` 调用父类构造，完成父类属性的初始化。
    

## 二、 方法覆盖（Override）的五大红线

当父类方法无法满足子类需求时需要重写。重写必须严格遵守以下规则（简记：**“两同、两小、一大”**）：

1. **两同**：方法名、形参列表必须与父类**完全一致**。
    
2. **两小**：
    
    - **返回值协变**：子类重写方法的返回值类型必须与父类一致，或者是父类返回值类型的**子类**（仅限引用类型）。
        
    - **异常抛出**：子类重写方法抛出的受检异常不能比父类更多、更大。
        
3. **一大**：
    
    - **访问权限**：子类的访问权限**必须 $\ge$ 父类**的访问权限（允许扩大，禁止缩小）。
        
4. **💡 两个绝对不能重写**：
    
    - **私有方法（private）**和**构造方法**无法被子类继承，因此绝对不能被重写。
        
5. **@Override 注解**：仅在**编译期**生效，强行校验当前方法是否符合重写规则，不符合则直接报错。
    

## 三、 终极对比消灭混淆

### 1. 方法重写（Override）方法重载（Overload）

|**特征**|**方法重写 (Override)**|**方法重载 (Overload)**|
|---|---|---|
|**发生范围**|**父子类之间**（具有继承关系）|**同一个类中**|
|**方法名**|必须相同|必须相同|
|**形参列表**|**必须相同**|**必须不同**（个数、类型、顺序）|
|**返回值类型**|必须相同（或为其子类）|完全无关|
|**应用场景**|子类不满足父类逻辑，重新实现（如猫狗重写“叫声”）|同样功能，支持传入不同参数（如 `println()`）|

### 2. 实例方法 🆚 实例变量（重名时的本质区别）

在 Java 中，**方法看对象（动态绑定），变量看类型（静态绑定）**：

- **方法重名 ➡️ 重写（Override）**：支持多态。向上转型对象调用时，**看 `new` 谁就执行谁**。可以用 `super.methodName()` 强行调用父类。
    
- **变量重名 ➡️ 隐藏（Hiding）**：**不支持多态**。重名变量在堆内存中**并存**，调用时**看声明的类型是谁就拿谁的值**。可以用 `super.fieldName` 访问父类同名变量。
    
- **静态方法重名 ➡️ 静态遮蔽**：静态方法依附于类，不参与多态。标注 `@Override` 会直接报错，调用时同样只看声明类型。

## 五、继承底层逻辑
### 1. 核心大局观：三大内存区域的联动

当你在 `main` 方法中执行以下这行代码时，JVM 会瞬间联动三个内存区域：

```
Rectangle rect = new Rectangle("矩形", "绿色", 2, 3);
```

1. **方法区（Method Area）**：负责加载类信息。存放 `Shape.class` 和 `Rectangle.class` 的结构、方法代码（如 `display()`、`area()`）。
    
2. **栈内存（Stack）**：负责当下的执行。`main` 方法对应的栈帧里，会产生一个局部变量 `rect`（它只是一个占 4 或 8 字节的引用地址指针）。
    
3. **堆内存（Heap）**：负责存储真实数据。分配一块内存给新建的 `Rectangle` 对象。
    

### 2. 堆内存的底层真相：大蛋糕包裹小蛋糕

这是继承里最迷人的部分。当你 `new Rectangle(...)` 时，堆内存中绝对不是只生成了子类的属性，而是采用了一种“组合包裹”的内存模型。

### 内存布局：

- **外层/下层（子类特有区）**：存放子类自己定义的变量，如 `width = 2;`、`height = 3;`。这里的隐式访问指针是 `this`。
    
- **内层/核心（父类特征区）**：存放父类定义的所有变量。**无论父类的变量是用 `public` 还是 `private` 修饰，它们都真真实实地存在于这个核心区内**，如 `name = "矩形";`、`color = "绿色";`。这里的隐式访问指针是 `super`。
    

> 💡 **为什么必须先调用父类的构造方法 `super()`？** 因为子类对象在堆内存初始化时，必须先在核心区把父类的这块“内芯”给浇筑好、赋上值（通过父类构造器），接着才能在外层扩展出子类自己的属性。

### 3. 方法调用的底层逻辑：向上爬梯子

当你在代码中调用方法时，方法本身**并不会**拷贝到堆内存的对象里。对象里只有一个隐藏的指针（Class Pointer）指向方法区。

我们来看执行 `rect.display();` 和 `rect.area();` 时，JVM 的底层查找轨迹：

#### 轨迹一：调用子类重写的方法 `rect.area();`

1. JVM 拿着 `rect` 变量里记录的堆内存地址（如 `0x1122`），找到堆中的对象。
    
2. 通过对象头部的类指针，直接冲向方法区里的 `Rectangle.class`。
    
3. 在 `Rectangle.class` 中一眼就找到了 `area()` 方法的代码，当场执行，利用堆里外层的数据 `width * height` 返回结果。**查找结束**。
    

#### 轨迹二：调用直接继承的方法 `rect.display();`

1. JVM 同样先通过对象找到方法区里的 `Rectangle.class`。
    
2. 查找后发现：`Rectangle` 类里并没有写 `display()` 方法。
    
3. **关键动作（向上追溯）**：JVM 不会放弃，它会顺着 `Rectangle.class` 头部记录的 `extends Shape` 箭头，**向上爬到父类 `Shape.class` 的领地**。
    
4. 在 `Shape.class` 中成功找到了 `display()` 方法，开始执行！
    

### 4. 终极闭环：为什么继承的方法能访问父类的 private 变量？

现在我们把“堆内存的包裹模型”**和**“方法区的向上查找”结合在一起，看清 `rect.display()` 执行的最后一幕：

1. JVM 跑到父类 `Shape.class` 拿到了 `display()` 的执行指令。
    
2. `display()` 的代码指令是：_“去目标对象的内存里，读取 `name` 和 `color` 打印出来。”_
    
3. 此时，JVM 携带着 `display()` 的执行权，反向跨回堆内存中地址为 `0x1122` 的那个对象。
    
4. **权限生效**：因为 `display()` 本质上是 `Shape` 自己的方法，所以当它跨回堆内存时，**它拥有最高权限，可以直接破开内层核心的隔离墙，精准读取到被 `private` 保护的 `name` 和 `color` 数据**。
