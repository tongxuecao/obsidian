#### 核心设计思想

> **抽取公共，强行规范。** 当父类中有些方法**无法实现**或**没有实现意义**（如 `Pet` 的 `eat()`）时，定义为抽象类。
> 
> - **父类责任**：提供**公共代码**（通用的属性、普通方法、以及供子类调用的构造方法）。
>     
> - **子类责任**：将具体的业务实现**强行交给子类**去做。
>     

#### 一、 语法定义速查

##### 1. 抽象类的定义

```
abstract class 类名 {
    // 【关键点】：包含构造方法，无法实例化（不能 new），专供子类使用！
    public 类名() { 
        System.out.println("抽象父类的构造方法被调用了");
    } 
}
```

##### 2. 抽象方法的定义

```
abstract 返回值类型 方法名(形参); // 【没有方法体】，直接以分号结束
```

#### 二、 深度解密：既然不能 `new`，抽象类的构造方法有什么用？

很多初学者会疑惑：既然 `Pet` 是抽象类，不能 `Pet p = new Pet()`，那它的构造方法写来干嘛？

**核心本质：供子类初始化父类特征。** 在 Java 中，子类的任意一个构造方法在执行时，第一行默认都会有一句隐藏的 `super()`。当实例化子类对象（如 `new Dog()`）时，子类必须先调用抽象父类的构造方法，在堆内存中开辟出父类的属性空间（如 `name` 属性），接着才执行子类自己的构造器。

#### 三、 核心规则“三大红线”（牢记不忘）

1. **强行交接绑定**：类中有抽象方法，类**必须**声明为抽象类；但抽象类中不一定非要有抽象方法。
    
2. **强行重写契约**：非抽象子类继承抽象类，**必须重写并实现**父类所有的抽象方法。
    
3. **天敌关键字**：`abstract` 绝对不能和 **`private`**、**`final`**、**`static`** 关键字共存。
