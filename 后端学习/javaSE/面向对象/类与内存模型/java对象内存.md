## 🔍 核心内存区域深度拆解

### 1. 虚拟机栈（JVM Stack，简称“栈”）

- **角色：** 线程私有的临时工作台。
    
- **存什么：** **局部变量表**（包含基本数据类型 `int`, `double` 等，以及对象的**引用地址**）、方法出口、操作数栈。
    
- **分配规则：**
    
    - 每当一个方法被调用，JVM 就会在栈中为这个方法压入一个“栈帧（Stack Frame）”。
        
    - 方法里的局部变量就声明在栈帧里。
        
    - 方法一旦执行完毕，对应的栈帧就会立刻被**弹栈销毁**，内存瞬间释放。它的速度仅次于 CPU 寄存器。
        

### 2. 堆（Heap，简称“堆”）

- **角色：** 线程共享的“中央大仓库”，也是 JVM 内存中最大的一块。
    
- **存什么：** **所有 `new` 出来的实体**（包括对象实例、数组、集合等）。
    
- **分配规则：**
    
    - 只要看到 `new` 关键字，就会在堆内存中开辟一块连续（或离散）的空间来存放这个对象的实际数据（如对象的属性值）。
        
    - 堆中的数据不会随方法的结束而消失。只有当一个对象没有任何引用指向它时，它才会变成“垃圾”，等待 **GC（垃圾回收器）** 在未来的某个时刻来清理它。
        

### 3. 方法区（Method Area）

- **角色：** 存放程序“元数据”的档案馆。
    
- **存什么：** **类的信息**（类的名字、方法代码、父类是谁）、**运行时常量池**、静态变量（`static` 修饰的变量）。
    
- **分配规则：** 在类加载器（ClassLoader）把 `.class` 文件读入内存时，这些信息就被固化到了方法区。在 JDK 8 之后，它的物理实现改为了**元空间（Metaspace）**，直接使用的是本地物理内存。
    

### 4. 程序计数器（Program Counter Register）

- **角色：** 线程专属的“行号指示器”。
    
- **存什么：** 只有极小的一块内存，记录当前线程正在执行的字节码指令地址。
    
- **分配规则：** CPU 会在多个线程之间来回切换（时间片轮转），当一个线程被挂起后重新唤醒时，它需要知道自己刚才执行到哪一行了，程序计数器就是用来干这个的。它是**唯一一个在 JVM 规范中没有规定任何 `OutOfMemoryError`（内存溢出）的区域**。
    

### 5. 本地方法栈（Native Method Stack）

- **角色：** 为 JVM 调用底层操作系统服务（C/C++ 代码）的专用栈。
    
- **存什么：** 比如 `Thread.sleep()`、`System.currentTimeMillis()` 等带有 `native` 关键字的方法，它们的执行状态和局部变量保存在这里。
    

## 💡 代码在内存里的实际运行轨迹

我们用一段简单的代码，来看看**栈、堆、方法区**是如何三方联动的：

Java

```
public class Dog {
    String name; // 成员变量

    public void bark() {
        int volume = 10; // 局部变量
        System.out.println(name + "汪汪叫，音量:" + volume);
    }
}

public class Main {
    public static void main(String[] args) {
        Dog myDog = new Dog(); // 核心分配发生在这里
        myDog.name = "旺财";
        myDog.bark();
    }
}
```

### 🎯 内存流转三部曲：

1. **类加载阶段（方法区）：** JVM 启动时，先把 `Main.class` 和 `Dog.class` 加载到**方法区**，拿到这两个类的结构图纸。
    
2. **创建对象（栈与堆的桥梁）：**
    
    - 在`main()`方法的栈帧里，创建了一个局部变量 `myDog`（呆在**栈**里）。
        
    - 在**堆**内存中，真正开辟了一块空间存放 `Dog` 实例，里面包含 `name` 属性（默认是 `null`）。
        
    - **连线：** 栈里的 `myDog` 变量保存了堆中这个 `Dog` 实例的**十六进制内存地址**（就像手里拿着堆对象的门牌号）。
        
3. **方法调用（栈内演练）：**
    
    - 当执行 `myDog.bark()` 时，一个新的栈帧 `bark()` 被压入**栈顶**。
        
    - `bark()` 栈帧内部生成了局部变量 `volume = 10`。
        
    - 当通过 `this.name` 访问名字时，JVM 根据 `myDog` 顺藤摸瓜找到**堆**里的对象，把 `null` 改成了 `"旺财"`。
        
    - 方法执行完，`bark()` 栈帧瞬间弹出销毁，`volume` 消失。

## 🚨 常见的内存报错（面试必问）

如果你的代码写得不够健壮，就会引发以下两种经典的内存灾难：

- **`StackOverflowError`（栈溢出）：**
    
    - **原因：** 栈帧的数量超过了栈的深度。
        
    - **常见场景：** 没有出口的死循环**递归调用**。方法一层套一层，栈帧无限压入，最后把栈空间撑爆了。
        
- **`OutOfMemoryError: Java heap space`（堆溢出/OOM）：**
    
    - **原因：** 堆内存中存放的对象实在太多、太大，超过了机器允许的最大值，且 GC 无法回收它们。
        
    - **常见场景：** 死循环往一个 `List` 集合里不停地 `add` 大对象，导致垃圾回收器误以为这些对象“还有用”，无法清理，最终内存耗尽。


*构造方法/constructor/构造器

1，构造方法有什么作用？
作用1：对象的创建（通过调用构造方法可以完成对象的创建）
作用2：对象的初始化（给对象的所有属性赋值就是对象的初始化）

2．怎么定义构造方法呢？
[修饰符列表]构造方法名(形参列表）{
构造方法体;
注意：
构造方法名必须和类名一致。
构造方法不需要提供返回值类型。
如果提供了返回值类型，那么这个方法就不是构造方法了，就变成普通方法了。

3，构造方法怎么调用呢？
使用new运算符来调用。
语法：new构造方法名(实参);
注意：构造方法最终执行结束之后，会自动将创建的对象的内存地址返回。但构造方法体中不需要提供“return值；”这样的语句。

4.在java语言中，如果一个类没有显示的去定义构造方法，系统会默认提供一个无参数的构造方法。（通常把这个构造方法叫做缺省构造器.)
5，一个类中如果显示的定义了构造方法，系统则不再提供缺省构造器。所以，为了对象创建更加方便，建议把无参数构造方法手动的写出来。

6.在java中，一个类中可以定义多个构造方法，而且这些构造方法自动构成了方法的重载（overload）。
7.构造方法中给属性赋值了？为什么还需要单独定义set方法给属性赋值呢？
在构造方法中赋值是对象第一次创建时属性赋的值。set方法可以在后期的时候调用，来完成属性值的修改。

8.构造方法执行原理？
构造方法执行包括两个重要的阶段：
第一阶段：对象的创建
第二阶段：对象的初始化
对象在什么时候创建的？
new的时候，会直接在堆内存中开辟空间。然后给所有属性赋默认值，完成对象的创建。（这个过程是在构造方法体执行之前就完成了。）
对象初始化在什么时候完成的？
构造方法体开始执行，标志着开始进行对象初始化。构造方法体执行完毕，表示对象初始化完毕。

9，构造代码块？
语法格式：{ }
构造代码块什么时候执行，执行几次？
每一次在new的时候，都会先执行一次构造代码块。
构造代码块是在构造方法执行之前执行的。
10．构造代码块有什么用？
如果所有的构造方法在最开始的时候有相同的一部分代码，不妨将这个公共的代码提取到构造代码块当中，这样代码可以得到复用。
