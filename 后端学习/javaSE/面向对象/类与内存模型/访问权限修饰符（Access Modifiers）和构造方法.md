| **修饰符**             | **同一个类中** | **同一个包（package）中** | **子类（含不同包的子类）** | **所有人（所有包）** |
| ------------------- | --------- | ------------------ | --------------- | ------------ |
| **`public`**        | ✓         | ✓                  | ✓               | ✓            |
| **`protected`**     | ✓         | ✓                  | ✓               | ✗            |
| **`default`**（默认不写） | ✓         | ✓                  | ✗               | ✗            |
| **`private`**       | ✓         | ✗                  | ✗               | ✗            |
## 🔍 四种修饰符的详细拆解与应用场景

### 1. `public`（公共的）

- **权限范围：** 宇宙级开放。只要能导入这个包，任何人、任何地方都能访问。
    
- **应用场景：**
    
    - **对外提供的接口/API：** 比如工具类的方法（如 `Math.sqrt()`）、Spring 框架中的 Controller 接口。
        
    - **实体类的主类：** 一个 `.java` 文件中唯一的公开类必须是 `public`。
        
    - **常量：** 通常配合 `static final` 使用（如 `public static final int MAX_CONNECTIONS = 100;`）。
        

### 2. `protected`（受保护的）

- **权限范围：** 家族式管理。同一个包里的类可以访问；不同包的类不行，除非你是我的**亲儿子（子类）**。
    
- **应用场景：**
    
    - **专门留给子类重写或使用的方法：** 比如你在写一个设计模式（如模板方法模式），父类定义了一个核心流程，有些步骤希望子类去实现或调用，但不希望外部普通用户直接碰。
        
    - _经典框架例子：_ Spring 框架或 Servlet 中的某些底层生命周期方法（如 `init()` ），通常会用 `protected` 限制，防止业务代码误调用。
        

### 3. `default`（默认的 / 包访问权限）

- **权限范围：** 同乡会（不写任何关键字）。只有在同一个包（Package）里的类才能访问，一旦跨包，哪怕是子类也访问不到。
    
- **应用场景：**
    
    - **包内部的组件协作：** 当你开发一个功能模块，里面有 5 个类互相配合工作，但你只希望其中 1 个 `public` 类作为模块的“代言人”对外部暴露，另外 4 个类就可以不写修饰符。这样它们在包内沟通无阻，包外的人根本看不到它们，保持了模块的整洁性。
        

### 4. `private`（私有的）

- **权限范围：** 极度自私。只有在**当前类内部**才能访问，出了这个类的括号 `{}`，谁来都不好使。
    
- **应用场景：**
    
    - **绝大多数的成员变量：** 比如用户的密码、银行余额（正如上一题所说，为了封装性，属性一律 `private`）。
        
    - **类内部的辅助方法（Tool Method）：** 一个复杂的业务方法被拆成了 3 个小步骤，这 3 个小步骤不需要也绝不应该让外部知道，那就把它们写成 `private`。
        
    - **防止被实例化的构造方法：** 比如单例模式（Singleton）或者工具类（如 `java.util.Arrays`），为了不让别人 `new` 出来，构造方法必须是 `private`。
        

## 🛠️ 最佳实践小建议

写代码时，应该坚持 **“权限最小化原则”**：

1. **能用 `private` 就用 `private`**。先全部封死，发现需要暴露给外部时，再逐步放开权限。
    
2. 类中的属性全部 `private`，配合 `public` 的 Getter/Setter。
    
3. 不要偷懒不写修饰符（变成 `default`），除非你明确知道这个类或方法只在当前包内流转。



## 1. 构造方法的“三大怪”

构造方法和普通的成员方法长得完全不一样，它有三个硬性规定：

1. **名字必须和类名完全一模一样**（大小写也必须一致）。
    
2. **绝对没有返回值类型**，连 `void` 都不能写。
    
3. **不能被手动像普通方法那样调用**（比如不能写 `p.Person()`），它只能配合 `new` 关键字在对象出生时自动触发一次。

**“一旦你手动写了任何一个有参构造方法，Java 赠送隐形无参构造的福利就会立刻取消！“
如果还是编译器就会无情报错。**
所以，**最佳实践是：只要写了有参构造，务必手动把无参构造也补写上！**

一个类可以拥有多个构造方法，只要它们的**参数列表不同**（参数个数、类型或顺序不同）即可，这叫**构造方法重载**。

## 面试终极一问：构造方法能被继承吗？

> ❌ **答案是：绝对不能！**
> 
> **原因很简单：** 构造方法的名字必须和当前类名一致。如果老爸叫 `Father`，儿子叫 `Son`。如果儿子继承了老爸的构造方法，那儿子的类里就会出现一个叫 `public Father()` 的方法，这直接违反了“构造方法名字必须和类名一致”的铁律！
> 
> 虽不能继承，但儿子可以用 `super()` 关键字去调用老爸的构造方法，帮自己初始化从老爸那里继承过来的公共属性。
