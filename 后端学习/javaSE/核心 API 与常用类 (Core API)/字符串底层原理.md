#### 扩展底层原理 3：字符串拼接的底层原理

- 如果没有变量参与，都是字符串直接相加，编译之后就是拼接之后的结果，会复用串池中的字符串。
- 如果有变量参与，会创建新的字符串，浪费内存

Java 对**纯字符串字面量拼接（无变量）**会在**编译阶段**做 **常量折叠（Constant Folding）** 优化，`"a" + "b"` 在编译后会直接变成 `"ab"`，运行时和直接写 `"ab"` 行为、性能完全一致。

为什么SpringBuilder提高效率？
所有要拼接的内容都会往 StringBuilder 中放，不会创建很多无用的空间，节约内存

SpringBuilder底层原理
- 默认创建一个长度为 16 的字节数组
- 添加的内容长度小于 16，直接存
- 添加的内容大于 16 会扩容（原来的容量 * 2+2）
- 如果扩容之后还不够，以实际长度为准

能存中文的原理
`byte` 数据类型的大小是 **1 个字节（8 位 / 8 bits）**。
**Java 8 及以前**，`StringBuilder` 底层使用的是 `char[]` 数组。如果你存的都是普通的英文字母，也会使用两个字节储存，造成的内存的浪费。
从 **Java 9 开始**，JDK 开发者对 `StringBuilder` 和 `String` 的底层进行了重构，将 `char[]` 变更为 **`byte[]`** 结合一个编码标记位（coder）。
- 如果字符串只包含 Latin-1 字符（如英文字母、数字），底层就用 **1 字节的 `byte`** 来存，内存直接**省下一半**。
- 如果包含中文字符（UTF-16），则会自动切换用 **2 个字节**来存。



虽然 `StringBuilder` 会自动扩容，但**扩容和数据拷贝是有性能开销的**。

如果你在开发中已经预知到大概要拼接的数据量（例如要拼接一个循环 1000 次的字符串），**强烈建议在初始化时就指定好容量**：

```
// 坏习惯：频繁触发扩容，多次申请内存和拷贝数据
StringBuilder sb = new StringBuilder(); 

// 好习惯：预估好大小，一次性到位，全程不触发扩容
StringBuilder sb = new StringBuilder(2048); 
```
