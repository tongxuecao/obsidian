### 1. 什么是局部变量表（Local Variable Table）

当一个线程调用一个 Java 方法时，JVM 会为这个方法创建一个**栈帧（Stack Frame）**。栈帧里面有两个最核心的区域：

1. **操作数栈（Operand Stack）：** 专门用来做计算的“临时工作台”（后进先出）。
    
2. **局部变量表（Local Variable Table）：** 专门用来存放方法参数和方法内部定义的局部变量的“储物柜”。
    

#### 局部变量表的特点：

- **容量在编译期确定：** 方法内最多需要多少个储物柜（Slot，槽），在代码编译成 `.class` 文件时就已经完全确定了（可以通过 `javap -v` 查看 `max_locals`）。
    
- **存储单元是 Slot（槽）：** * `boolean`, `byte`, `char`, `short`, `int`, `float`, `reference`（对象引用）占用 **1 个 Slot**。
    
    - `long` 和 `double` 占用 **2 个 Slot**。
        
- **索引访问：** 局部变量表就像一个数组，通过索引（0, 1, 2...）来访问。
    
    - 如果是非静态方法（Instance Method），**索引 0 默认是 `this` 指针**。
        

### 2. 什么是 `iload` 和 `istore`？

在 JVM 的指令集里，数据不能直接在局部变量表里做加减乘除，必须先把数据拉到**操作数栈**里。而 `iload` 和 `istore` 就是数据在**局部变量表**和**操作数栈**之间来回搬运的“搬运工”。

- **`iload` (Integer Load)：** 将一个 `int` 类型的局部变量从**局部变量表**中“复制”出来，压入**操作数栈**的栈顶。（**读变量**）
    
- **`istore` (Integer Store)：** 将**操作数栈**栈顶的 `int` 类型数值弹出来，存入**局部变量表**的指定位置。（**写/赋值变量**）
    

> **小贴士：** 开头的 `i` 代表 `int` 类型。如果是 `float` 就是 `fload`/`fstore`，如果是对象引用就是 `aload`/`astore`。

### 3. 极简代码演练：看透底层的搬运过程

```
public void calc() {
    int a = 10;
    int b = 20;
    int c = a + b;
}
```

这段代码编译后的字节码（Bytecode）和底层的执行逻辑如下：

| **字节码指令**          | **局部变量表状态 (Local Variables)**    | **操作数栈状态 (Operand Stack)** | **详细解释**                           |
| ------------------ | -------------------------------- | -------------------------- | ---------------------------------- |
| **`0: bipush 10`** | `[0: this]`                      | `[10]`                     | 将常量 `10` 压入操作数栈。                   |
| **`2: istore_1`**  | `[0: this, 1: 10]`               | `[]`                       | 将栈顶的 `10` 弹出，存入局部变量表索引 1（即变量 `a`）。 |
| **`3: bipush 20`** | `[0: this, 1: 10]`               | `[20]`                     | 将常量 `20` 压入操作数栈。                   |
| **`5: istore_2`**  | `[0: this, 1: 10, 2: 20]`        | `[]`                       | 将栈顶的 `20` 弹出，存入局部变量表索引 2（即变量 `b`）。 |
| **`6: iload_1`**   | `[0: this, 1: 10, 2: 20]`        | `[10]`                     | 从局部变量表索引 1 复制出 `10`，压入操作数栈。        |
| **`7: iload_2`**   | `[0: this, 1: 10, 2: 20]`        | `[10, 20]`                 | 从局部变量表索引 2 复制出 `20`，压入操作数栈。        |
| **`8: iadd`**      | `[0: this, 1: 10, 2: 20]`        | `[30]`                     | 弹出栈顶两个数（10和20）相加，把结果 `30` 压回栈顶。    |
| **`9: istore_3`**  | `[0: this, 1: 10, 2: 20, 3: 30]` | `[]`                       | 将栈顶的 `30` 弹出，存入局部变量表索引 3（即变量 `c`）。 |

_(注：`istore_1` 是 `istore 1` 的简写形式，JVM 为了节省字节码空间，对 0-3 号索引做了特殊单字节指令优化)_

## 总结

对于高级工程师来说，理解这个可以帮你秒懂很多 Java 现象：

- **为什么局部变量必须初始化才能用？** 因为局部变量表创建后，Slot 里面是空（或垃圾值），不像堆内存的对象属性会被分配默认值。不通过 `store` 指令写值，直接 `load` 就会报错。
    
- **什么是垃圾回收的 GCRoots？** 局部变量表中正在引用的对象（`astore` 进去的 `reference`），就是最典型的 GCRoots 之一。

方法中的参数传递：

基本数据类型和引用数据类型本质上都是相同的，将自身的值复制一份传递给参数（参数也是局部变量），只不过引用数据类型值相同时就是指向的同一个地址，所以在方法中和方法外部操作同一个对象。
