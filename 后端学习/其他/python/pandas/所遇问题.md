## 🔍 疑问一：Pandas 中的核心统计函数到底怎么运行？

在面对实验中关于高考分数线和白葡萄酒品质的数据时，你接触到了 Pandas 最灵魂的几个高频组合拳，你的疑问主要集中在它们的底层逻辑上。

### 1. 对 `sorted(df['column'].unique())` 的理解

- **遇到的现象**：为什么输出结果中会带有奇怪的 `np.int64(3)` 这种字样？
    
- **深度理解**：
    
    - **分层剥离**：我们由内到外将其拆解为：**提取列 $\rightarrow$ `.unique()` 去重（返回无序 NumPy 数组） $\rightarrow$ `sorted()` 排序（返回 Python 原生列表）**。
        
    - **数据形态**：之所以显示 `np.int64`，是因为 Pandas 追求高性能，底层依赖 NumPy 的 64 位整数。当它被放入 Python 列表打印时，触发了追求准确性的原始形态显示（`__repr__`）。使用 `.tolist()` 即可将其还原为干净的原生整数。
        

### 2. 对 `df.groupby()` 与 SQL 的映射理解

- **遇到的核心函数**：`df.groupby('quality')['fixed acidity'].mean()`
    
- **深度理解**：
    
    - **三步模型**：理解 `groupby` 必须建立 **“拆分 (Split) - 应用 (Apply) - 组合 (Combine)”** 的动态画面。它把大表按类别切片进“小抽屉”，对各抽屉独立计算，最后合并。
        
    - **SQL 映射**：它与 SQL 中的 `GROUP BY` 思想完全一致。`.groupby()` 对应 `GROUP BY`，后面的方括号对应 `SELECT` 的目标字段，`.mean()` 对应 `AVG()` 聚合函数。
        
    - **返回值本质**：不加聚合函数的 `groupby` 返回的是一个**懒加载的中间对象**，它在幕后建立了行索引的映射（可以通过 `.groups` 查看），只有调用聚合函数时才真正爆发计算。
        

### 3. 对 `[[]]` 双括号嵌套提取多列的理解

- **遇到的核心代码**：`df3[['sepal_length', 'petal_length']]`
    
- **深度理解**：外层方括号是 Pandas 的**提取算子**，内层方括号是一个**标准的 Python 列表**。双括号本质上是把一个“列名列表”传给提取器。单括号返回一维的 `Series`，双括号则能返回保持二维结构的 `DataFrame`。
    

## 🛠️ 疑问二：后端开发中的警告与报错如何精准修复？

随着你开始独立动手编写鸢尾花（Iris）的脚本，代码进入了实战阶段，随之而来的是高频的工程细节问题。

### 1. 副本修改警告（`SettingWithCopyWarning`）

- **遇到的现象**：在对 `df1` 进行多列 `sort_values(..., inplace=True)` 排序时，Jupyter 弹出了长长的黄色警告。
    
- **深度理解**：
    
    - **根源在于前一步**：你在用 `df1 = df[[...]]` 挑出特定列时，Pandas 在内存里创建的只是一个指向母表的“影子（视图）”。你在影子上面做 `inplace=True` 原地修改，Pandas 无法确定你是否想联动修改母表，从而引发安全警告。
        
    - **完美闭眼解法**：在切片提取数据时，随手加上 **`.copy()`** 明确断绝父子关系，在内存中开辟独立空间，警告就会彻底消失。同时，现代标准更推荐采用 `df1 = df1.sort_values(...)` 的重赋值写法，代替 `inplace=True`。
        

### 2. 多列去重失败

- **遇到的现象**：对 DataFrame（多列表格）调用 `df2.unique()` 导致报错。
    
- **深度理解**：`.unique()` 是一维 `Series` 独有的方法。对于二维表格 `DataFrame`，必须使用 **`.drop_duplicates()`**。它能提供更丰富的控制，比如通过 `keep='first'/'last'` 决定重复数据留哪一行，通过 `subset` 指定仅对某几列去重。

### 对于python Series and DataFrame理解

虽然DataFrame的行是由Series组成的,但是DataFrame[columns]取得列，因为在DataFrame中，相同列的的元素属性相同，含义相同，数据统计常常对列处理。
series 也可以看作key/value字典，DataFrame可以看作key/value[]字典，由列索引可以找到整列元素，由多个Series组成的DataFrame,相同的index对应的含义相同，同上描述。
可以理解一个series（行）包含一个事物的多个属性，对于一列，则是一类事物的相同属性，数据统计经常操作相同属性的数据，找到规律。
